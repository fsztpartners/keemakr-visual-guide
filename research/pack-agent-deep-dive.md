## What activates each folder?

### Takeaway
The pack contains a business application around its conversation workers. Draw an application wiring map, not a list of definitions. There are independent build/catalog and runtime paths.

### Cited Findings
- **Authored blueprint — kee.project.ts** imports tables, app requirements, named event identities, eventHandlers, capabilities implementations, inbound agents, JOBS. It describes what Core can install/discover, not a process that starts every file. [ClinicOS blueprint imports,1–14](/Users/sobingt/projects/covalify/clinicos/kee.project.ts:1).

### Inferences
Adding a new feature needs answers to four concrete questions: **Which door starts it? Which registry exposes it? Which function does the work? Which Core grant authorizes its effects?** A helper needs an import/call; an agent tool needs Eve tool registration/discovery; a capability needs a contract + binding + registry + Core install; event reaction needs identity + handler registration + delivery; job needs registry + admin-enabled schedule + runtime work authority.

### Gaps
No exhaustive dead-code scan, generated Eve bundle inspection or deployed artifact comparison performed. Do not label an arbitrary file orphan merely because one search did not find it. The Sales conversion example below is a demonstrated unwired stub, not proof all handlers are unwired.
